# 3-Stage Pipeline для параллельных агентов

## Концепция

Pipeline разделяет сложную задачу на 3 этапа с параллельным выполнением где возможно.

```
┌─────────────────────────────────────────────────────────────┐
│  STAGE 1: Research (2 параллельно, Gemini)                  │
│  ┌──────────────┐    ┌──────────────┐                       │
│  │ researcher A │    │ researcher B │                       │
│  │ (web search) │    │ (docs/KB)    │                       │
│  └──────────────┘    └──────────────┘                       │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│  STAGE 2: Execution (1-2 последовательно, ZAI)              │
│  ┌──────────────┐    ┌──────────────┐                       │
│  │ main-worker  │───▶│   coder      │                       │
│  │ (exec/write) │    │ (scripts)    │                       │
│  └──────────────┘    └──────────────┘                       │
└─────────────────────────────────────────────────────────────┘
                           ↓
┌─────────────────────────────────────────────────────────────┐
│  STAGE 3: Review (2 параллельно, Gemini)                    │
│  ┌──────────────┐    ┌──────────────┐                       │
│  │  reviewer    │    │   critic     │                       │
│  │ (качество)   │    │  (критика)   │                       │
│  └──────────────┘    └──────────────┘                       │
└─────────────────────────────────────────────────────────────┘
```

## Когда использовать

| Сценарий | Подходит? |
|----------|-----------|
| Создание нового проекта | ✅ Да |
| Анализ и отчет | ✅ Да |
| Рефакторинг кода | ✅ Да |
| Простой вопрос | ❌ Нет (overkill) |
| Срочная задача | ❌ Нет (последовательно быстрее для простого) |

## Пример использования

### Задача: "Создать CLI для анализа логов"

**Stage 1: Research (2 агента параллельно)**
```javascript
// Агент A
sessions_spawn({
  agentId: "quick-research",
  model: "openrouter/google/gemini-2.5-flash-lite",
  task: "Исследуй: парсинг JSONL файлов в Python..."
})

// Агент B (одновременно)
sessions_spawn({
  agentId: "quick-research", 
  model: "openrouter/google/gemini-2.5-flash-lite",
  task: "Исследуй: best practices для CLI на Python..."
})
```

**Stage 2: Execution (последовательно)**
```javascript
// После завершения Stage 1
sessions_spawn({
  agentId: "main-worker",
  task: "Создай CLI утилиту на основе research..."
})
```

**Stage 3: Review (2 агента параллельно)**
```javascript
// После завершения Stage 2
sessions_spawn({
  agentId: "quick-research",
  task: "Проверь качество кода..."
})

sessions_spawn({
  agentId: "quick-research",
  task: "Проверь функциональность..."
})
```

## Метрики производительности

| Подход | Время | Параллельность |
|--------|-------|----------------|
| Последовательно | ~10+ мин | 1 агент |
| Pipeline | ~3 мин | 2 параллельно на этапах 1 и 3 |
| **Выгода** | **3x** | |

## Ограничения

1. **Память:** MacBook Air 8GB → max 2 параллельных агента
2. **Rate limits:** Gemini Lite — стабильно 2, ZAI — 1-2
3. **Контекст:** Main должен агрегировать результаты

## Шаблон для Main

```markdown
## Запуск Pipeline

### Stage 1: Research
- [ ] Запустить 2 research агента параллельно (Gemini)
- [ ] Дождаться результатов
- [ ] Агрегировать findings

### Stage 2: Execution  
- [ ] Запустить main-worker с агрегированным контекстом
- [ ] Проверить созданные файлы

### Stage 3: Review
- [ ] Запустить 2 review агента параллельно (Gemini)
- [ ] Собрать рекомендации
- [ ] Применить исправления если нужно
```
